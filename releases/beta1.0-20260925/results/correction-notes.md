# 修正记录与结果解释

本轮保持最终英文 prompt 不变；修复的是生成器的机械退化和不安全词义替换。Q1 按可构造方法随机选择；Q2 不再全量添加固定前缀；T3 添加场景对应的具体假设案例。

Q1 实际例子：
```text
The customer explicitly confirms resolution
→ The client expressly confirms resolution
```

Q2 实际例子：
```text
Does this convey urgency?
→ Is a need for prompt attention conveyed here?
```

Q1 739 个空格候选、73 个词汇候选。词汇可构造范围有限，不能将此分布当作全部理论可行方法的均匀抽样。Q2 697 个实质词汇改写、115 个句子改写。所有候选从 beta 原题生成；程序结构检查和本轮针对性抽查不代替全量独立语义审核。

原题严格错误 81/812（9.98%），其中 Score 67/161（41.61%）。原题额外重复产生 4/731（0.55%）新增错误；Q1 的 7/731 和 Q2 的 10/731 是本轮小幅变化，不能全部归因于攻击，更不能从两次调用推断稳定攻击能力。

T2 新增 158 题错误由 Noul 16、Choice 56、Score 86 构成；T3 新增 111 题由 Noul 6、Choice 25、Score 80 构成。当前较明显的变化集中在 T/P 和 Q3，且总数受严格 Score 计分影响很大。Score 标准没有放宽。

S1/S2/S3 各自 812 个请求输入 token 数均与原题相同。S2 解码后本来相同；S1/S3 的结果与辅助字段被忽略的解释相容，但没有服务端模型输入日志，机制未证实。不能把 S3 的低错误率视为抵抗误导观点的证明。

本轮 11,368 次请求全部 HTTP 200，其中 9,744 个对抗输入、812 个原题、812 次完全相同请求体的原题对照。主要评测峰值并发 1,000；重复对照 812。验证了 10,556 个请求体哈希与严格计分，以及 812 个重复请求体相等。
